# Cloudflare 用量与费用监控：需求基线与设计建议

日期：2026-10-23（北京时间）。状态：本地版本已实现并核查，等待用户确认页面；来源与计费的部分覆盖见验收文档，尚未部署。下文保留已确认需求基线。

## 1. 目标及交付顺序

在一个 Cloudflare 账户中，展示可可靠取得的各产品用量、包含额度、剩余额度和已产生的额外费用，帮助用户发现费用风险。

交付顺序固定为：本地开发与联调 → 用户查看、调整并确认本地页面 → Cloudflare 部署 → 线上复核。页面确认前不创建远程数据库、不上传 Worker、不设置生产 Secret、不开启自动发布。读取现有账户的 API 不属于部署，可以用于本地联调。

## 2. 已确认的需求

| 领域 | 约束 |
| --- | --- |
| 账户 | 一个账户，同时支持账户级和用户级两个只读 Token |
| 覆盖 | Workers Paid 全部计费维度，以及账户下其他可能产生费用的 Cloudflare 产品；不能以熟悉的少数产品名单替代完整核查 |
| 组织 | 总览和独立产品页面；各产品、各额度分开展示，不混用单位或周期 |
| 指标 | 展示已用、额度、剩余、百分比、计量单位、适用周期、数据时间和来源；额度与平台硬性限制分别标注 |
| 展示稳定性 | 确认无法获取且没有替代来源的指标排除；成功无记录的指标保留；暂时失败的指标固定保留，不随刷新出现或消失 |
| 刷新 | 每次打开或重新加载网页自动刷新一次，另有手动刷新按钮；内部产品导航复用本次结果 |
| 无定时任务 | 无固定缓存有效期、无后台采集、无轮询、无页面定时刷新、无窗口聚焦或网络重连自动重取 |
| 历史 | 不保存历史采样序列，不做每日趋势、预测或耗尽时间；保存最新结果及各指标最后一次成功结果用于失败兜底 |
| 费用 | 已发生的超额费用，固定费与用量费分列；实际账单数据优先，计算结果标注估算；不将 Free 超额后的服务限制虚算成费用 |
| Token | 网页填写、验证、保存、替换、清除两个 Token；不回显完整 Token，不要求增加监控 Token 写权限 |
| 访问 | 全站不增加登录或其他身份认证，设置页同样遵循此约定 |
| 外观 | shadcn/ui、浅色、科技感、丰富且有意义的动画，适配手机 |
| 图表 | 动态环形额度图和进度条等当前状态图，明确显示剩余量；图形与数值一致，超额不截断真实数字 |
| 通知 | 只在页面内醒目预警，无外部通知，无自动停用产品功能 |
| 性能 | 减少 Worker CPU、API 重复请求、D1 实际扫描及写入行数；不以返回行数或 SQL 条数替代成本依据 |

以下属于本设计建议的默认值，不声称用户逐项指定过：中文文案、美元金额、北京时间展示，预警阈值 80%／90%／100%。底层周期计算保留 Cloudflare 的 UTC 边界，界面同时明确周期类型和换算后的起止时间。

## 3. 方案比较与建议

| 方案 | 适用性与取舍 |
| --- | --- |
| React SPA + Worker API + D1（建议） | 静态资源直接分发；接口、Token 解密和计算在 Worker；本地模拟 D1，与生产运行时接近；适合多产品页面和图表 |
| 服务端渲染框架 | 此项目不需要 SEO 或每次请求生成 HTML；引入更多运行时工作和框架约束，收益有限 |
| 单文件页面配少量脚本 | 初始体积小，但产品适配、稳定状态管理、shadcn 组件和测试更难维护 |

采用建议方案编排计划。技术选择由开发者提出，用户要求的页面验收和部署顺序不变。

技术组成：React、TypeScript、Vite、Cloudflare Vite plugin、shadcn/ui、Tailwind CSS、Lucide 图标、按需使用的 Motion、原生 SVG 当前额度图、Worker Fetch API、D1 binding、Web Crypto、Vitest、浏览器验收。依赖在初始化时确认稳定版本兼容性并锁定 lockfile；不为了监控系统额外引入 DO、Queues、KV、Containers 或 SSR。

## 4. 覆盖清单与来源审查

先建立产品与计费维度登记表，再编写适配器。登记表对照账户订阅、官方计费文档与价格目录、实际资源清单、统计 schema 和权限响应，逐个记录：产品、meter、来源、单位、周期、包含额度、计价规则、适用计划、Token 类型、完整性、保留期、可见性和验证证据。

首批必须覆盖审查的家族包括：

- Workers 请求／CPU、Pages Functions 归属计量、Builds、Observability／Logs／Logpush、Workers for Platforms／动态 Workers。
- D1、KV、Durable Objects（SQLite 与旧 KV 后端分别计量）、R2（Standard、IA、读取取回、操作类别）、R2 Data Catalog／SQL、Artifacts。
- Queues、Workflows、Containers 的 CPU／内存／磁盘／区域流出、Hyperdrive、Vectorize、Pipelines、Analytics Engine。
- Workers AI、AI Search、AI Gateway、Browser Rendering、Web Search、Email Service、Secrets Store。
- Images（存储、分发、唯一转换分开）、Stream（存储、播放等）、Realtime／TURN 等账户可用服务。
- 域名与区域计划、Registrar 续费、Zero Trust 订阅、Argo／Smart Shield／Cache Reserve、Load Balancing、Spectrum、Zaraz、证书与其他账户订阅／按量附加服务。
- 订阅和官方目录发现的新增、独立、旧版或合同型产品。不可访问的合同明细记录审查结论，不编造额度或价格。

该清单是审查起点，不是所有 Cloudflare 产品的封闭枚举。旧版 meter、别名和多个 API 对同一计费维度的记录要归一去重；停用或遗留产品必须核查当前可用性后再决定是否进入展示。

### 来源核查边界

每个使用者的 Token 权限、套餐、来源保留期可能不同，需在运行时独立核查；公开文档不保存具体账户结果。Logpush 的配置权限与统计权限分开判断，Builds 的空对象不能解释为用量零，Argo/Cache Reserve 必须由明确的产品状态确认未开通。

GraphQL Settings 的保留期不能假设覆盖所有账期。Images 分发等来源可能不足以覆盖长账期：不增加后台累计任务，不以局部窗口冒充完整账期，不在账期尾部悄悄删除指标；保留范围不足状态，只有确认永久无法可靠获取时才稳定排除。其他独立可读指标分别保留。

## 5. 页面与视觉

页面路由建议为 `/` 总览、`/products/:productId` 各产品、`/settings` 设置。产品可以在侧栏按类别分组，但每个产品保留独立页面。手机使用抽屉导航，关键数据和手动刷新无需 hover 即可访问。

总览显示账户／账期、额度预警、已监控费用、产品入口和最近刷新状态；不同周期不拼成一个假百分比。产品页先呈现最重要的剩余量，再呈现分项额度、费用构成和来源说明。无免费额度、无限制、未开通、仅硬限制的指标使用相应状态，不强行画百分比。

绘制桌面总览、Workers 详情、设置，以及手机对应状态的完整视觉概念，提取颜色、字体、留白、图标和动效规范后实现。概念稿用于开发比对，用户最终验收对象是本地可交互页面。模拟异常数据只能用于独立演示／测试场景，并明确标注，不混入真实账户模式。

动态图表显示同一时刻的已用、剩余与超出量；数值是主证据，颜色与图形辅助阅读。超额时圆环可以填满，但数字仍显示实际比例、超出量和费用。动画用于进入、刷新后数值过渡、hover／tap 和预警；隐藏、离屏或系统偏好减少动态效果时降低或暂停动画。动画不驱动任何 API 轮询。

## 6. 稳定指标状态

将“是否展示”与“本次测量结果”分开保存。

- 可见性登记：`visible` 或 `excluded`；排除必须有确定原因和替代来源核查证据。
- 本次状态：`ok`、`no_records`、`not_enabled`、`error`、`partial`。
- 单次超时、429、5xx、网络错误、Token 失效或普通 401／403，都不能直接把已有指标排除。
- `no_records` 只有在正确来源、正确周期且响应完整时成立；空对象、空旧接口、采样值和暂未入账需要独立判断。
- 读取失败保留最后成功值及其时间，并明确标注非本次数据；从未成功取得的用 `—`，不伪造零或剩余 100%。
- 可见性只在首次完整能力审查、用户主动重新核查、Token 配置或明确订阅变化后的能力审查中更新；常规刷新不能根据“本次是否有值”筛卡片。
- 部分指标失败不阻断其他成功指标更新；页面布局和指标顺序保持稳定。

## 7. 数据、接口与刷新

共享数据契约位于 `shared/dashboard.ts`。金额和可能超过安全整数范围的用量以十进制字符串传输；小数计价采用明确精度的十进制运算，币种和单位必须随值传递。

建议接口：

| 接口 | 职责 |
| --- | --- |
| `GET /api/bootstrap` | 脱敏设置、稳定登记表、最新快照；无 Token 明文 |
| `PUT /api/tokens/:kind` | 验证并保存一个 Token，核对账户一致性，保留另一 Token |
| `DELETE /api/tokens/:kind` | 清除一个 Token，返回配置状态 |
| `POST /api/capabilities/recheck` | 设置页主动重新核查可用指标；不会代替普通刷新 |
| `POST /api/refresh` | 唯一的用量更新入口，reason 仅为 `open` 或 `manual` |

网页打开先展示已保存结果和时间，再发起一次真实更新；没有 Token 时引导设置，不虚构数据。根级控制器管理刷新，React 开发模式重复挂载、快速连点和内部导航不重复触发。切回窗口、重连网络或时间流逝不自动刷新。刷新中的按钮有明确状态，避免重入。

后端复用同一请求内的账户资料、Token 解密结果和基础查询；兼容的统计合并查询，分页与有界并发适用于资源清单。按接口记录首选 Token 和有依据的备用来源，不能对所有错误无差别重试两遍。请求失败只做有界处理，避免重试风暴。对累计接口重查整个所需区间并覆盖，不能把每次返回的累计值再次相加。

## 8. 费用与额度

每个 meter 独立定义 daily／calendar-month／subscription-cycle／instant 等周期、包含额度、单位换算、舍入和阶梯规则。存储容量字节与 GB-month 分开；最大容量限制与免费包含额度分开；R2 操作分类、DO 后端、Browser 并发等不能以总请求数或瞬时值替代计费值。

同一个 meter 在账单和统计中同时出现时只计一次费用。账单金额、按价估算、尚未计价分开标注；固定订阅费与当前账期已产生超额费用分开。未知、范围不足、价格未核实的项目不能记成 $0，也不能让总额看似完整。Free 产品超限后阻止请求的，只呈现超限／限制，不虚构超额收费。没有免费额度的产品从第一笔可计费用量开始计算，不能等待百分比超过 100%。

价格元数据保留官方来源、核实日期、适用计划和有效范围；初始化及上线前核实当前价格。自定义合同、折扣、税费、信用额若没有可靠数据，明确估算范围，不伪造最终发票金额。

## 9. Token 与 D1 最小持久化

Token 通过网页提交给同源 Worker，Worker 使用 Web Crypto AES-GCM 加密后写入 D1。随机 nonce 与密文保存，加密主密钥放 Worker Secret；本地使用被忽略的 `.dev.vars` 保存随机开发主密钥。两个只读监控 Token 不承担部署／修改 Worker Secret 的职责。完整 Token 不进入浏览器持久化、响应、日志、Git、演示数据或构建产物；页面只显示保存状态、验证时间和遮罩尾号。

采用两张单例表作为起始设计：

| 表 | 内容 |
| --- | --- |
| `dashboard_settings`，整数主键 `id=1` | 配置版本、两个 Token 的密文及脱敏元数据、能力登记表 |
| `dashboard_state`，整数主键 `id=1` | 快照版本、各指标最新成功值、本次结果状态、尝试／成功时间 |

不建立历史表或冗余二级索引。设置保存只改设置，普通刷新只改当前快照；失败不覆盖成功值。不存每次请求、错误或资源快照的历史数组。并发更新与 Token 轮换使用版本比较，旧配置的迟到响应不能覆盖新配置结果。单例 JSON 的容量和序列化成本需要实测；只有真实体积证明必要时才按产品拆行，不先建立复杂存储层。

## 10. 性能和验收边界

- SPA 与静态资源直接分发，仅 `/api/*` 进入 Worker；不加入 SSR 或额外监控运行时。
- 以正常打开、手动刷新、结果不变、部分失败、保存 Token、静态资源访问为性能样本。
- D1 记录实际 `rows_read`／`rows_written`，结合 `EXPLAIN QUERY PLAN` 证明主键点查；统计包含索引维护影响，不把返回行数当扫描量。
- 记录接口数、重复请求、响应体积、JSON 计算、前端动画开销与 Worker 代码体积；去掉无意义的存储和计算后再复测。
- 本地运行时的耗时／CPU profile 不是 Cloudflare 生产计费 CPU；页面验收前交付本地证据，部署后另测生产 CPU。
- 生产 CPU、线上 D1、生产路由与密钥验证必须在用户确认本地页面并允许部署之后完成，不提前宣称通过。

本地验收覆盖真实只读 API、正常／无记录／未开通／超额／短暂失败状态、两个 Token 保存、账户一致性、费用边界、桌面与手机、页面间导航、手动刷新。超额和错误场景采用明确标注的测试数据，不制造真实消费。

## 11. 部署与剩余开发责任

默认准备 `workers.dev` 发布，不在计划阶段索取域名；若用户部署时指定域名，再按其指定配置。上线前核对目标账户、部署权限、D1 绑定、生产主密钥和构建产物。两个监控 Token 继续只读，部署使用已有 OAuth／Wrangler 授权，权限缺失时明确缺失项。

本地与生产密钥、数据库隔离；不直接复制本地密文到使用不同主密钥的生产库。生产 Token 通过已实现的网页配置入口保存。交付部署版本、访问地址、费用／数据覆盖说明和回滚步骤，不把发布成功当作线上验收成功。
